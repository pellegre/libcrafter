# Oracle Scapy Migration Inventory

This file records the Scapy surface that must migrate behind `tools/oracle`.
It is an inventory only; step 01 did not move code.

## Searches Run

The inventory is based on these repository searches, excluding local execution
state under `.internal workflow/` and generated outputs under `target/`:

```bash
rg -n --glob '!.internal workflow/**' --glob '!target/**' 'scapy'
rg -n --glob '!.internal workflow/**' --glob '!target/**' 'from scapy'
rg -n --glob '!.internal workflow/**' --glob '!target/**' 'import scapy'
rg -n --glob '!.internal workflow/**' --glob '!target/**' 'scapy>='
rg -n --glob '!.internal workflow/**' --glob '!target/**' 'tests/fixtures/scapy'
```

An additional case-insensitive file list was checked for `Scapy` doc comments
and API compatibility wording.

## Required Compatibility Commands

These current commands must keep working during migration. Later steps may turn
them into compatibility wrappers over `tools/oracle/run`, but their user-facing
entrypoints should remain available until the migration explicitly removes or
renames them.

| Command | Current role | Migration requirement |
| --- | --- | --- |
| `tools/reference/check-scapy-interop` | Main offline Scapy/libcrafter interop runner. Selects fixture cases, generates Scapy vectors, runs the Rust `scapy_reference` test, emits libcrafter vectors, validates them with Scapy, and optionally runs pcap interop. | Preserve options such as `--only`, `--family`, `--direction`, `--smoke`, `--out`, and `--keep-artifacts`; eventually delegate to oracle offline/pcap modes. |
| `tools/reference/generate-scapy-fixtures` | Bootstrap wrapper for `tools/reference/scapy-fixtures.py`; uses existing Python, `uv`, or a local venv with `scapy>=2.5,<3`. | Preserve fixture regeneration and drift-check behavior until oracle owns fixture generation. |
| `tools/reference/check-reference-interop` | Generic alias that currently `exec`s `tools/reference/check-scapy-interop`. | Keep as the backend-neutral compatibility name and retarget it to oracle first when possible. |
| `tests/live/scapy-interop.sh` | Live-suite entrypoint that records versions and runs `tools/reference/check-reference-interop` default and pcap checks. | Keep the suite contract and artifact layout while later delegating to oracle live/offline surfaces. |
| `tools/live-lab/libcrafter-live-lab run --provider local-dry-run --suite scapy-interop` | Provider-level dry-run command that invokes `tests/live/scapy-interop.sh --dry-run`. | Keep working for local lab smoke coverage; later it should call the oracle-backed suite without changing the provider command. |

## Inventory By Category

### Backend Execution Logic

These files contain Scapy-specific packet construction, decoding, pcap handling,
normalization, or dependency bootstrap. Their logic should move under
`tools/oracle/engine/backends/scapy/` in later steps.

| Path | Current Scapy surface | Migration target |
| --- | --- | --- |
| `tools/reference/scapy-fixtures.py` | Imports Scapy, bootstraps Scapy if needed, defines Scapy packet factories, decodes generated bytes back through Scapy, writes `.bin` and `.json` fixture artifacts, and stores `scapy_root`, `scapy_show`, and `scapy_version` metadata. | Split into Scapy bootstrap, packet materialization, and normalization modules under the oracle Scapy backend. |
| `tools/reference/scapy-validate-libcrafter.py` | Imports Scapy, bootstraps it with `uv` or a venv, decodes libcrafter-generated vectors, validates root/layer/field expectations, and writes decoded Scapy artifacts. | Move decode and normalization behavior into oracle `libcrafter_to_reference` validation. |
| `tools/reference/scapy-pcap-interop.py` | Imports Scapy pcap APIs, writes Scapy pcaps, reads libcrafter pcaps, and validates bidirectional pcap agreement. | Move to oracle pcap mode and backend pcap adapter. |
| `tools/reference/generate-scapy-fixtures` | Shell bootstrap wrapper that directly checks `import scapy.all` and installs `scapy>=2.5,<3` through `uv` or a venv. | Keep as a legacy wrapper; centralize bootstrap in oracle. |

## Dependency Bootstrap Matches

Current `scapy>=2.5,<3` bootstrap logic exists in:

- `tools/reference/scapy-fixtures.py`
- `tools/reference/scapy-validate-libcrafter.py`
- `tools/reference/scapy-pcap-interop.py`
- `tools/reference/generate-scapy-fixtures`
- `tests/live/common.sh`
- `tools/live-lab/providers/hetzner`

Oracle should centralize this into `tools/oracle/engine/backends/scapy/bootstrap.py`
and leave older entrypoints as compatibility wrappers or callers of that
central bootstrap.
